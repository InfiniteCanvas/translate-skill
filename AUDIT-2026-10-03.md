# Adversarial audit — `novel-translator`

**Date:** 2026-10-03
**Commit audited:** `903371e` (HEAD at time of audit)
**Scope:** `novel-translator/scripts/**`, `novel-translator/assets/**`, `novel-translator/*.md`,
`novel-translator/references/*.md`, `tests/**`
**Baseline:** `uv run tests/run_all.py` → **28 passed, 0 failed**

## Method

Five adversarial agents, one per workstream, dispatched in parallel:

| WS | Workstream | Files |
|---|---|---|
| WS1 | Pipeline + LLM client correctness | `translate.py`, `pipeline.py`, `client.py`, `config.py`, `project.py` |
| WS2 | Doc-mirror drift | `file-formats.md`, `SKILL.md`, `README.md`, `ingestion.md`, `assets/**` |
| WS3 | Glossary / TN / review / replace / fix logic | `glossary.py`, `balance.py`, `tn.py`, `tn_recheck.py`, `review.py`, `review_notes.py`, `fix.py`, `replace.py`, `story.py` |
| WS4 | Output + external-process layer | `epub.py`, `assemble.py`, `cover.py`, `autobuild.py`, `vcs.py` |
| WS5 | Tests + dead code | `tests/**`, dead-code sweep of `lib/` |

Each agent was required to cite `file:line` **and** supply evidence for every claim, and to mark
anything unconfirmed as `UNVERIFIED` rather than guessing. Every finding was then re-verified
against source in the orchestrator context; every high/critical claim additionally went through a
dedicated refutation pass whose only job was to disprove it.

**Result:** 47 findings claimed, **38 survived**, 2 overturned by refutation, 7 rejected on the
reporting agent's own evidence. No criticals remain.

## High

### H1 — `review fix`'s `--project` guard is bypassed by argparse abbreviation
`lib/fix.py:266` · code

The guard skips any command whose argv contains a token `== "--project"` or starting with
`"--project="`:

```python
if any(
    tok == "--project" or tok.startswith("--project=")
    for tok in spec.argv
):
```

`translate.py` never sets `allow_abbrev`, so argparse keeps its default and binds any unambiguous
prefix (`--proj`, `--pro`) to the same option. `main()` resolves `project_action` ahead of the
prepended `project_global` (`translate.py:1674`), so the smuggled value wins.

Found independently by two separate audit agents; survived every refutation attempt
(parser default, dest precedence, guard coverage, downstream re-checks).

- **Trigger:** a hand-edited or injected `review-report.md` line — `fix.py:263` states the report
  is explicitly hand-editable, which is exactly the threat model the guard exists for.
- **Impact:** `glossary replace` / `glossary retire` executed against an attacker-chosen project
  directory. Bounded: the verb allowlist holds, there is no `shell=True`, argv is a fixed
  `sys.executable script_path` invocation — this is **not** arbitrary code execution.
- **Fix:** pass `allow_abbrev=False` to every parser in `_build_parser()`. That closes the whole
  abbreviation class rather than enumerating spellings.

### H2 — The "foreign repository" guard is an existence check, not an identity check
`lib/vcs.py:133` · code

```python
# A repo without our .gitignore was not created by ensure_repo(): it is
# the user's own repository, and `git add -A` would sweep their pending
# changes into a skill-labeled commit.
if not (project_dir / ".gitignore").exists():
```

`GITIGNORE` (`vcs.py:28-34`) is never compared against; only presence is tested, and essentially
every real repository has a `.gitignore`. `ensure_repo` writes it only when absent (`vcs.py:104`)
and returns `[]` early when the directory is already a repo (`vcs.py:97`).

- **Trigger:** `init` in a directory that is already the user's own repo and has a `.gitignore`.
- **Impact:** `git add -A` runs under a skill-labeled subject, sweeping the user's pending
  unrelated work into one commit. Recovery is `git reset` on a sha the skill helpfully printed.
  Commit hygiene, not data loss.
- **Fix:** require exact content match against `GITIGNORE`, or write a marker into `.git/` at
  `ensure_repo` time and gate `commit` on it.

### H3 — `init` resets glossary/tn_history/story_state without `--force`
`translate.py:296` · code

```python
glossary.save(project_dir, glossary.empty())
paths["tn_history"].write_text("{}\n", encoding="utf-8", newline="\n")
paths["story_state"].unlink(missing_ok=True)
```

Unconditional. The only barrier in `cmd_init` is `if paths["config"].exists() and not args.force`
(`translate.py:165`). The console line at `:293` prints `[init] --force: resetting …` regardless of
whether `--force` was passed.

Docs are correct and the code is not: `SKILL.md:85-88` and `README.md:68-72` both attribute the
reset exclusively to `--force`.

- **Trigger:** `config.json` deleted or corrupt, then the documented recovery `init --title … --author …`
  re-run without `--force`. The entire model-grown glossary, note-gap history, and story recaps
  are destroyed.
- **Fix:** gate `translate.py:296-298` on `args.force`. Add a doc sentence covering the
  deleted-`config.json` case either way.

### H4 — The significance gate is bypassed by nickname/variant absorption
`lib/pipeline.py:495` · code

In `_apply_glossary_proposal`, a proposal whose source is not an existing entry first scans all
terms for a nickname match and `return`s — **before** the `min_occurrences` check below it.
Variants added via `union_variants` are never gated.

- **Trigger:** a proposal for `修` with translation `"Cultivation"` while `修炼` → `"Cultivation"`
  already exists (`"修" in "修炼"`).
- **Impact:** a one-occurrence string becomes a permanently matchable variant, consumes a slot in
  the `contextual_glossary_cap` (200) prompt budget, and inflates its occurrence count in the
  balance check.
- **Fix:** run the count against `src` before the nickname loop, or move the nickname check after
  the gate.

### H5 — `review fix` has no conflict guard; two findings on one field both apply
`lib/review.py:687` (has the guard) vs `lib/fix.py:262` (does not) · code

`apply_fixes` — the in-review path — detects and skips conflicting suggestions on the same
`(entry, field)`. The offline report path does not: it executes `- Command:` bullets in file order.
`review_glossary` dedupes only on `(source, kind)`, so two findings of different kinds that both
map to `glossary replace` both survive and both run.

- **Impact:** the first command sets translation A and rewrites every chapter; the second sets B and
  rewrites them all back. Both exit 0, both counted `applied`, each triggering its own
  `vcs.commit`.
- **Fix:** key resolved specs on `(normalized source, target flag)` in `run_commands` and skip
  later duplicates with a `[review fix] skipped: conflicting suggestion` line.

### H6 — `cmd_status` is never invoked by any test
`translate.py:691` · test

`grep -rn "cmd_status" tests/` → **no callers**. The only test touching the subcommand is
`tests/test_parser_project.py:173`, which calls `parse_args` and asserts only the resolved project
dir; its own docstring says "Parsing only — no project directories are created or touched".

Commit `3398887` claims "status degrades cleanly on unreadable glossary and non-dict
`novel_info`" (`translate.py:733-736` and `:739-745`). Neither is pinned; reverting the
`try/except` entirely leaves the suite green.

- **Fix:** ~15 lines. Build a project with `glossary.json = "[1,2]"` and `novel_info.json = "[]"`,
  call `cmd_status` under `redirect_stdout`, assert exit 0, assert the `[warn] unreadable`
  substring, assert no traceback.

### H7 — `main()`'s exit-code mapping is unpinned for every non-zero path
`translate.py:1687` · test

`translate.main()` is called exactly once in the suite (`tests/test_review_notes.py:667`) and
asserts `code == 0`. `test_fix_guard.py:178,247,414` spawns the real CLI via `fix.run_commands`,
but every such assertion checks `failed == 0` / `applied == 1`. No test exercises any non-zero arm
of the `try` block at `translate.py:1680-1697`.

Commit `3398887` claims "main() maps ValueError to `[FAIL]` exit 2". Unpinned.

- **Fix:** one `subprocess.run` case asserting `returncode == 2`, `[FAIL]` on stderr, and no
  `Traceback` — a corrupt chapter frontmatter on the `glossary count` path is the exact trigger the
  commit cites.

## Medium

### M1 — `init` rewrites source chapters non-atomically, before any backup exists
`lib/project.py:156` (via `:231`, `:260`) · code

`write_chapter` is a plain `Path.write_text`, not `atomic_write_text`. `cmd_init` runs
`backfill_frontmatter` (`translate.py:314`) and `sync_manifest` (`:318`) — both of which rewrite
every fresh chapter because `order` is absent — while `vcs.ensure_repo` does not run until
`translate.py:379`.

- **Trigger:** interrupt, full disk, or power loss between the truncating `open()` and the final
  write.
- **Impact:** one source chapter truncated with no in-project backup. Every other chapter is intact
  and re-derivable by a re-run, and the source is normally re-downloadable from `source_url`, which
  is why this sits at medium rather than critical.
- **Secondary:** `write_chapter` round-trips frontmatter through `yaml.safe_dump`, dropping comments,
  rewrapping long values, and — since `read_chapter` now reads `utf-8-sig` (`project.py:116`) —
  silently stripping the BOM the BOM-tolerance work was added to tolerate. This happens on every
  `sync`, crash or not.
- **Fix:** route `write_chapter` through `atomic_write_text`; move `vcs.ensure_repo` + an initial
  commit to the top of `cmd_init`.

### M2 — An empty-but-successful annotation deletes a good notes sidecar
`lib/tn_recheck.py:242→252`, `lib/tn.py:179` · code

`tn.save_notes` unlinks the sidecar when the kept list is empty. In `tn` re-check the annotator
counts as successful whenever the parsed object has a `notes` list — an empty list passes
(`tn_recheck.py:224-225`, which only checks `isinstance(raw_notes, list)`).

In the legacy-migration branch, `tn_recheck.py:242-250` first rewrites the translated markdown,
stripping the baked `[^N]` markers and the `## Translator's Notes` section, and only then calls
`save_notes`.

- **Trigger:** `tn --chapters N` on a chapter with a good sidecar where the annotator returns
  `{"notes": []}`. `tn_gap_chapters` (default 10) can suppress every candidate for a late chapter,
  making this realistic.
- **Mitigating:** the per-chapter line prints `[tn] <file>: N before -> 0 after`, and
  `vcs.commit` (`tn_recheck.py:279`) snapshots the deletion into git. The markdown-destruction
  variant applies only to the `did_migrate` branch, not to normal sidecar-based projects.
- **Fix:** treat "annotator returned zero usable notes while a non-empty baseline exists" as a
  failed evaluation, or give `save_notes` an explicit `allow_delete` flag the re-check path sets
  only when the baseline was empty.

### M3 — 11 of 12 external calls have no timeout and inherit stdin
`lib/vcs.py:58`, `lib/fix.py:308` · code

`_run` (wrapping six git call sites) and the `review fix` child invocation both pass no `timeout`
and leave stdin shared with the parent. There is no outer timeout in the pipeline.

- **Corrected vector:** the credential-prompt / ssh-host-key hangs are **not** reachable — there is
  no `push`, `fetch`, `pull`, or `clone` anywhere in the codebase. The real vector is `git commit`
  (`vcs.py:152`) running the user's `pre-commit` / `commit-msg` / `post-commit` hooks (including a
  global `core.hooksPath`) or `commit.gpgsign`, any of which blocks on stdin.
- **Fix:** `timeout=` on both, `stdin=subprocess.DEVNULL` on `_run`, and
  `GIT_TERMINAL_PROMPT=0` in the child env.

### M4 — `ingestion.md` says full-width digits are ignored; the code accepts them
`references/ingestion.md:43,147` · doc

Verified against the real regex:

```
'Chapter_0007.md' -> match: True | int(): 7
'Chapter_０００７.md' -> match: True | int(): 7
'Chapter_٠٠٠٧.md' -> match: True | int(): 7
```

`\d` on a `str` pattern matches all Unicode decimal digits and `int()` accepts them. The normative
regex block at `ingestion.md:25` is quoted correctly; the two prose statements built on it are
false.

- **Impact:** the file is discovered, enters `chapters.json` with `number: 7`, and collides with a
  genuine ASCII `Chapter_0007.md`. The user checks only the manifest count against the TOC (as the
  doc instructs) and the anomaly ships.
- **Fix:** tighten to `[0-9]` — almost certainly the intent — or correct the two prose claims.

### M5 — A non-numeric or null config value escapes `main()`'s exception mapping
`lib/pipeline.py:910` (and ~11 more sites) · code

```python
max_attempts = int(_cfg_value(cfg, "max_attempts"))
```

`load_config` deep-merges onto `DEFAULTS`, so `DEFAULTS` never rescues a bad user value:
`"max_attempts": null` reaches `int(None)` → `TypeError`, which is in **none** of `main()`'s except
arms (`CliError`, `PipelineError`, `ValueError`, `KeyboardInterrupt`, `OSError`).

- **Impact:** raw traceback instead of the documented `[FAIL]` + exit 2. The failure also lands at
  `pipeline.py:910`, *outside* the per-chapter retry, so it aborts the whole batch.
- **Fix:** validate/coerce in `_cfg_value` and raise `PipelineError` (already mapped to exit 2).

### M6 — The truncated-chunk "escalation" can de-escalate
`lib/pipeline.py:1000, 1135` · code

```python
escalated = min(int(round(max_out * 1.5)), provider_max)
```

When `providers.translator.max_tokens` < `translate_max_output_tokens`, `escalated < max_out`, so
the corrective retry for a truncated chunk re-sends at a **smaller** cap — guaranteed to fail for the
reason it fired, burning two LLM calls and a full attempt. The default config is safe
(`max_tokens: 16384` > `8192`), which is why this survives testing.

- **Fix:** `escalated = max(max_out, min(...))`, plus a load-time warning when the two disagree.

### M7 — Guide-only `unit` entries can never be auto-retired
`lib/balance.py:147`, `lib/pipeline.py:633` · code

The guide-only skip is correctly applied on all three balance tiers. But because
`_cleanup_drift_signals` only ever retires sources present in `signal_sources`, a `unit` entry is
excluded from balance-driven retirement permanently — and the category is freely assignable by hand
or by model with no warning.

- **Corrected:** such a term is **not** invisible to the glossary *review* tier —
  `_heuristic_findings` and `_model_findings` apply no category filter, and `mundane` still maps to
  `glossary retire`. Only the balance-driven path is closed.
- **Fix:** warn when `unit` is assigned to an entry with a non-empty translation, and/or restrict
  the skip to `origin == "seeded"` entries.

### M8 — Report-driven `--category` is unvalidated
`lib/review.py:408` · code

`apply_fixes` validates the category and skips with `"invalid category"` (`:707`);
`command_for_finding` does not, and emits `--category <free text>` verbatim. `REVIEW_SCHEMA`
constrains `kind` and `severity` with enums but leaves `suggestion` a free string.

- **Impact:** `glossary set_fields` raises `ValueError` → `CliError` → exit 2 → counted `failed` →
  `review fix` exits 1 for a finding `review glossary --fix` handles gracefully. With
  `--exit-on-error` it aborts every remaining finding.
- **Fix:** validate in `command_for_finding` (route invalid categories to the manual section).

### M9 — "epubcheck could not run" is reported as "validation failed"
`translate.py:118` · code

`epub.run_epubcheck` returns tri-state (`None` = could not run), but `if ok:` treats `None` as
failure. Every `util replace`, `glossary replace`, and `tn` on a machine without Docker prints
`[warn] epub auto-build failed validation` for a perfectly good EPUB. `cmd_build_epub`
(`translate.py:1432`) gets this right; `_maybe_autobuild` does not.

- **Fix:** branch on `ok is None` first.

### M10 — Docker infrastructure failures report as `epubcheck failed`, exit 1
`lib/epub.py:342`, `translate.py:1436` · code

Image not pulled (exit 125), daemon down (exit 1), and unshared volume path (125) all yield
`ok = False`. The docstring at `epub.py:322-323` claims `None` means "could not run at all"; it only
covers missing-binary and timeout.

- **Impact:** a batch caller branches on exit code and rebuilds forever against a machine that
  simply lacks a working Docker — inverting the stated design intent at `vcs.py:13-14`.
- **Fix:** match on output substrings (`Unable to find image`, `Cannot connect to the Docker
  daemon`) or pre-check with `docker info` / `docker image inspect`, and return `None`.

### M11 — `atomic_write_text` does not create the parent directory
`lib/project.py:94` vs `lib/pipeline.py:341` · code

Confirmed: `atomic_write_text` raises `FileNotFoundError` on a missing parent. Nine of ten call
sites guarantee it explicitly; `save_state` (`draft/<stem>.state.json`) inherits `draft/` solely
from `translate.py:210`. No migration creates it.

- **Trigger:** a pre-`draft/`-era project migrated v001–v007, then run with `translate`, fails on
  the first chunk flush and surfaces as `TRANSLATE failed: FileNotFoundError`.
- **Fix:** add `path.parent.mkdir(parents=True, exist_ok=True)` to `atomic_write_text` itself.

### M12 — The Windows replace retry is 0.4s total; exhaustion fails a correct chapter
`lib/project.py:73-80, 96-101` · code

Five attempts × 0.1s. A reader holding the destination open — Defender, Explorer preview, OneDrive,
Calibre, or the parallel epub child the docstring names — routinely holds for seconds.

- **Impact:** the `finally` deletes the fully-written temp; the exception propagates through
  `save_manifest` (`pipeline.py:1392`) and marks an already-correct chapter `needs-review`, so the
  next `translate --next` re-translates it and burns a full chapter of API spend.
- **Fix:** exponential backoff over ~5s, and make the manifest write best-effort with a `[warn]`.

### M13 — No consolidated exit-code contract; `SKILL.md:606` mislabels exit 1
`SKILL.md:606` · doc

Eight of nine exit-1 sites are enumerated per-command in prose. `build-epub`'s **two** distinct
codes (1 = epubcheck failed, 2 = builder crashed) and `profile`'s 1 and `ping`'s 2 appear nowhere.
There is no table.

- **Impact:** an agent scripting the CLI reads `SKILL.md:606`, sees exit 1, and reports "chapters
  need review" when `build-epub` actually means "the epub is malformed".
- **Fix:** add an exit-code table to `file-formats.md`; also fix the module docstring at
  `translate.py:10-13`, which omits `profile`.
