# CLI reference

Generated from `scripts/translate.py`'s argparse tree by
`scripts/gen_cli_doc.py` -- **do not edit this file by hand**:

```bash
uv run scripts/gen_cli_doc.py            # rewrite it from the parser
uv run scripts/gen_cli_doc.py --check    # fail if it is stale, write nothing
```

`tests/test_cli_doc.py` regenerates this file in memory and compares the bytes,
so a subcommand or flag that lands without regenerating fails the gate.

This is the single source for **which commands exist and what they accept**.
`SKILL.md`, `README.md` and `references/maintenance.md` describe what each
command *does* and point here for the surface itself.
## Invocation

```bash
uv run scripts/translate.py <command> [--project <dir>] [options]
uv run scripts/translate.py <command> <action> [--project <dir>] [options]
```

`--project` defaults to the current directory and is accepted before the
subcommand, after it, and (for the nested actions) after the action, so all
three of these name the same project:

```bash
uv run scripts/translate.py --project <dir> status
uv run scripts/translate.py status --project <dir>
uv run scripts/translate.py glossary count --project <dir> <term>
```

The placeholder after a flag is argparse's own: the `metavar` when the command
sets one, otherwise the argument's internal destination name. That is why the
same `--project` flag reads `--project PROJECT` on a top-level command and
`--project PROJECT_ACTION` on a nested one -- the placeholder differs, the flag
does not, and both resolve the same directory.

### `glossary set`

edit metadata fields on a single entry (atomic, idempotent)

    translate.py glossary set [--project PROJECT_ACTION] [--no-verify] [--strict] --source TERM
        [--translation TEXT] [--definition TEXT] [--category CAT] [--add-variant V]
        [--remove-variant V] [--alt-translations LIST] [--add-alt A] [--remove-alt A]

| argument | default | meaning |
|---|---|---|
| `--project PROJECT_ACTION` | (unset) | project directory (default: current directory) |
| `--no-verify` | false | skip the post-edit glossary drift check and its status flip |
| `--strict` | false | exit non-zero when that check confirms drift (governs the exit code only; a confirmed chapter is flipped either way) |
| `--source TERM` | (unset) | glossary source term (matched by source or variants) (required) |
| `--translation TEXT` | (unset) | new translation (CJK-checked against the source like apply_fixes) |
| `--definition TEXT` | (unset) | new definition (stored as-is; may quote source-language terms) |
| `--category CAT` | (unset) | new category (one of: place, person, org, skill, technique, level, state, item, honorific, unit, other) |

| `--add-alt A` | [] | append A to the entry's alt_translations (repeatable) |
| `--remove-alt A` | [] | remove A from alt_translations (repeatable, no-op when absent) |

### `init`

initialize a project from source/ chapters

    translate.py init [--project PROJECT] --title TITLE --author AUTHOR [--source-url SOURCE_URL]
        [--source-lang SOURCE_LANG] [--target-lang TARGET_LANG] [--tags TAGS] [--api-base API_BASE]
        [--cover-url COVER_URL] [--style NAME|PATH|auto] [--background BACKGROUND] [--skip-profile]
        [--force]

| argument | default | meaning |
|---|---|---|
| `--project PROJECT` | (unset) | project directory (default: current directory) |
| `--title TITLE` | (unset) | novel title (original language) (required) |
| `--author AUTHOR` | (unset) | author name (required) |
| `--source-url SOURCE_URL` | (empty) | URL of the source novel |
| `--source-lang SOURCE_LANG` | zh | source language code (default: zh) |
| `--target-lang TARGET_LANG` | en | target language code (default: en) |
| `--tags TAGS` | (empty) | comma-separated tag list |
| `--api-base API_BASE` | (empty) | OpenAI-compatible API base URL written into the new project (omit to resolve the endpoint through config.local.json or the project's own config.json) |
| `--cover-url COVER_URL` | (unset) | URL to download the cover image from |
| `--style NAME\|PATH\|auto` | classic | style guide: a preset name, a path to a .md file, or 'auto' for a model-generated profile (default: classic) |
| `--background BACKGROUND` | (unset) | 2-4 sentences of novel background for the translator's context frame |
| `--skip-profile` | false | deprecated no-op for preset styles; still skips the LLM call for --style auto |

### `logs`

    translate.py logs [--project PROJECT] [--run RUN_ID] [--list] [--io | --no-io] [--json] [--last
        N] [--report] [--html] [spec]

At most one of: `--io`, `--no-io`.

| argument | default | meaning |
|---|---|---|
| `--project PROJECT` | (unset) | project directory (default: current directory) |
| `--run RUN_ID` | (unset) | select one run by exact id or unique prefix (scans all three buckets) |
| `--list` | false | list the available run ids with command, start time and chapter count |
| `--io` | (unset) | include prompt/response bodies (default: follow config log_prompt_bodies) |
| `--no-io` | true | metadata only |
| `--json` | false | emit one JSON object per event on stdout (and nothing else) |
| `--last N` | 1 | show the newest N runs (default: 1) |
| `--report` | false | regenerate each matched chapter's report.md from its retained runs |
| `--html` | false | write the project-wide HTML dashboard to logs/report.html (always whole-project; a SPEC does not narrow it; embeds the latest run's prompt/response bodies per chapter) |

### `review`

| argument | default | meaning |
|---|---|---|

## Shared options

argparse `parents=[...]` copies one action object into every child that lists it, so
these are declared once in `translate.py` and accepted widely. The same option spelling
declared independently by two commands is *not* shared -- it is two options, and each is
documented in its own section above.

- **`--no-verify`** (flag) -- skip the post-edit glossary drift check and its status
  flip. Accepted by `glossary merge`, `glossary replace`, `glossary retire`, `glossary
  set`.
- **`--project`** (PROJECT) -- project directory (default: current directory). Accepted
  by every command.
- **`--project`** (PROJECT_ACTION) -- project directory (default: current directory).
  Accepted by `glossary count`, `glossary merge`, `glossary replace`, `glossary retire`,
  `glossary search`, `glossary set`.
- **`--strict`** (flag) -- exit non-zero when that check confirms drift (governs the
  exit code only; a confirmed chapter is flipped either way). Accepted by `glossary
  merge`, `glossary replace`, `glossary retire`, `glossary set`.

## Exit codes

The one table here that argparse cannot supply. `references/file-formats.md` section
"Exit codes" remains normative and lists every command that can exit 1 and why; this is
the shared contract.

| exit | meaning | applies to |
|---|---|---|
| 0 | success, including a run that had nothing to do | every command |
| 1 | the command ran and its answer is negative: a chapter ended `needs-review`, epubcheck reported validation errors, a review report was refused as stale, a term sits below its significance floor, a search matched nothing, or a check confirmed a problem. Which commands can exit 1 is enumerated per command in `references/file-formats.md` section "Exit codes". | per command |
| 2 | usage or setup error -- bad arguments, a missing or corrupt project file, a provider array that resolves no endpoint. One `[FAIL]` line, never a traceback. Also `build-epub` when the builder subprocess itself crashes, and `ping` when a provider is unreachable. | every command |
| 3 | a provider call failed after exhausting its retries and the run stopped. No surviving candidate is substituted and no partial chapter is written; `references/file-formats.md` section "Provider failure is fatal" has the full ladder. | every command |
| 130 | interrupted at the keyboard (`Ctrl-C`) -- chapter state is saved, so re-running the same command resumes | every command |
